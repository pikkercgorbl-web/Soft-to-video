# Soft-to-video

Сценарий → Gemini → Chatterbox → Pexels/Pixabay. Текущая версия сохраняет
результаты отдельных этапов и возобновляет прерванную работу. Автомонтаж,
ComfyUI и звуковое оформление пока не реализованы.

## Установка

Рекомендуется отдельное окружение Python 3.11. Нужны FFmpeg/ffprobe в PATH,
запущенный внешний сервер Chatterbox и ключи провайдеров в `.env`.

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

Скопируйте `.env.example` в `.env` и заполните ключи. Не загружайте `.env` в Git.
Версия модели и зависимости сервера Chatterbox управляются отдельно.

## Запуск и возобновление

```powershell
python download_pexels.py --project history-demo --script script.txt
```

Повторите ту же команду для возобновления. Без `--project` имя строится из хеша
сценария: одинаковый сценарий открывает тот же проект. Для правок сценария с
переиспользованием неизменных фрагментов указывайте постоянное `--project`.
Имена проектов: латинские буквы, цифры, `_`, `-`.

Результаты находятся в `projects/history-demo/`:

- `scripts/` — версии исходного сценария;
- `visual/` — сохранённые поисковые запросы и визуальные описания;
- `audio/` — версии озвучки; исходный WAV при включённом сохранении в `raw/` рядом;
- `video/`, `photo/` — версии подобранного видеоряда;
- `run_summary.json` — результат последнего завершённого прогона и пути к актуальным файлам;
- журналы ошибок и выбора материалов.

Каждый этап имеет `state.json` со статусом `running`, `completed` или `failed`.
Оставшийся после аварии `running` будет повторён. Готовый результат используется
только при совпадении входов и SHA-256 выходного файла. Не удаляйте старые версии,
пока не убедились, что новая подходит. Старый каталог `downloads/` не очищается
и автоматически не импортируется.

Изменение визуальных настроек не сбрасывает аудио. Изменение текста, голоса,
настроек TTS, обработки звука, словаря или версии кода создаёт новую версию.
Кэш привязан к индексу чанка: вставка текста со сдвигом индексов может потребовать
повторной генерации следующих чанков. Изменение кода консервативно сбрасывает кэш.
Ключи API в манифесты не записываются.

### Внешний сервер и обновление голоса

Если на сервере заменили модель или содержимое референсного WAV под тем же именем,
клиент этого не видит. Обязательно увеличьте значение в `.env`:

```dotenv
TTS_CACHE_REVISION=2
TTS_LANGUAGE=ru
TTS_VOICE_FILE=1_.wav
TTS_VOICE_MODE=clone
```

`TTS_MODEL_ID` — необязательная подпись для диагностики и кэша. Она **не загружает
и не переключает** модель на сервере. Фактическую модель проверяйте по журналу
запуска сервера. Сохранённый `config.yaml` может отличаться от действующего.

Для проверки настроек без генерации и вызовов Gemini:

```powershell
python diagnose_tts.py --offline
python diagnose_tts.py
```

Вторая команда дополнительно проверяет TCP-соединение с адресом TTS (таймаут 5 с).
Доступный порт не доказывает исправность API или правильность загруженной модели.
Диагностика предупреждает о сочетании Turbo в сохранённом конфиге с русским языком.

### Ограничения первого этапа

- Ключи API пока нужны даже для запуска с полностью готовым кэшем.
- Озвучка и её постобработка пока составляют один этап: смена фильтров повторяет TTS.
- Нет автоматических повторов внутри одного запуска; повторная команда возобновляет работу.
- Только один процесс может обрабатывать один проект. Очередь TTS ограничивает
  параллелизм внутри процесса; не запускайте несколько разных проектов одновременно
  на одном TTS-сервере с ограниченной VRAM.
- Код возврата 0 означает готовность всех ожидаемых чанков, 1 — ошибку/неполный результат.
- Качество речи и работу на GPU нужно проверить на реальном локальном сервере.
- Хранилище использованных стоков остаётся общим `used_media.json`; существующая
  политика запрета повторов между запусками сохранена.

## Проверки без ключей, GPU и моделей

Для тестов достаточно лёгких зависимостей:

```powershell
pip install aiohttp requests google-genai python-dotenv filelock
python -m unittest discover -s tests -v
```

Провайдеры и генерация в тестах заменены заглушками. Проверяются восстановление,
повреждение/отсутствие файлов, смена настроек, независимость аудио от визуала,
сериализация TTS и блокировка одновременного запуска одного проекта.

## Контрольное сравнение хвостов Chatterbox

Подтверждённая по предоставленному пользователем логу модель —
`ChatterboxMultilingualTTS` на CUDA, 24 kHz. Сохранённый `config.yaml` сам по себе
не подтверждает активный Turbo. `forcing EOS ... long_tail=True` фиксирует
срабатывание эвристики; это не доказывает, что именно она породила слышимый шум.
Не отключайте защиту EOS на основании одного такого предупреждения.

Поместите исходный текст с U+0301 в `debug/chatterbox_report/chunk2_seg1.txt`.
Укажите в `.env` правильный сервер и тот же референс. Остановите другие запросы
к серверу на время эксперимента. Скрипт не меняет конфигурацию сервера.

```powershell
python debug/compare_tts_endings.py
python debug/compare_tts_endings.py --run
```

Первая команда только сохраняет план. Вторая отправляет 15 последовательных
запросов: 3 seed × 4 сочетания ударений (есть/нет) и exaggeration (1.0/0.5),
плюс повтор исходного сочетания на каждом seed для проверки воспроизводимости.
Остальные параметры совпадают. Порядок перемешивается воспроизводимо.
`--punctuation` добавляет ещё 3 запроса с многоточием: это отдельный эксперимент,
который меняет и интонацию. Не сравнивайте его как чистый тест разметки ударений.

Сохраняются точные WAV-ответы **без обработки**, payload, UTC-время запросов,
контрольные суммы и `review.csv`. Вручную оцените хвост, естественность, пропуски
слов и отметьте forced EOS по соответствующей сессии сервера. Одинаковый seed
не гарантирует полной детерминированности конкретного CUDA-сервера. Совпадение
длительности с номером шага — лишь косвенная привязка к старому логу.
После ошибки/таймаута эксперимент останавливается: сервер может ещё генерировать.
Запуски имеют отдельные каталоги, предыдущие файлы не перезаписываются.

Локальные голосовые образцы и логи исключены из Git. Для передачи на анализ
прикрепите нужные файлы или ZIP в чат. Не выкладывайте ключи из серверных логов.
